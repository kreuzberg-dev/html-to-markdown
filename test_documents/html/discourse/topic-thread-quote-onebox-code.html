I'm hitting a panic in our ingestion pipeline whenever a table has more than about 40 levels of nested <div> wrappers around the cell content. Repro is below — anyone seen this?

fn build_nested(depth: usize) -> String {
    let mut out = String::new();
    for _ in 0..depth {
        out.push_str("<div>");
    }
    out.push_str("<p>cell</p>");
    for _ in 0..depth {
        out.push_str("</div>");
    }
    out
}

Yeah, we hit this too. It's not actually the nesting depth itself — it's the combination of nesting plus a table cell that also contains a self-closing <br/> right before the closing tag. Workaround for now:

  1. Pre-flatten wrapper <div>s with a DOM pass before handing off to the converter
  2. Or cap recursion depth in your own preprocessing step and log a warning

Note: this is unrelated to the <table> rowspan bug from last month — that one was already fixed in 3.1.9.
